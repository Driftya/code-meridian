# CodeMeridian v1.0.45

This release adds JavaScript and JSX indexing to the existing ts-morph worker and fixes graph identity and relationship resolution for TypeScript workspaces nested below the repository root. It also documents where JavaScript analysis is necessarily less complete than TypeScript and excludes common generated-output directories from discovery.

## Highlights

### JavaScript And JSX Indexing

- Extended the shared TypeScript indexer to discover and index `.js` and `.jsx` alongside `.ts` and `.tsx` files.
- Added `jsconfig.json` project-root discovery, while retaining repository-root fallback for JavaScript projects without a TypeScript or JavaScript configuration file.
- Enabled JavaScript parsing through ts-morph with `allowJs` and preserved the existing node, edge, relationship-health, incremental-indexing, and file-role pipelines.
- Updated the unified indexer discovery and execution plan so JavaScript-only repositories invoke the shared worker.
- Added JavaScript and JSX test and configuration file-role defaults.
- Kept the existing `--skip-typescript` option as the switch for the shared TypeScript/JavaScript indexing pass.

### JavaScript Support Boundaries

- Documented that JavaScript graphs have less declared type evidence than TypeScript graphs, so typed `Uses`, member `Calls`, `Implements`, and some inheritance relationships can be less complete.
- Documented strongest support for ES modules and best-effort behavior for CommonJS, computed module paths, dynamic property access, prototype mutation, monkey patching, and other runtime-defined relationships.
- Clarified that JSDoc can improve compiler inference but is not guaranteed to produce first-class graph type nodes, and that indexing does not enable `checkJs` type checking.
- Clarified that JSX code relationships and HTML/CSS static class, ID, and stylesheet relationships are complementary indexing passes.

### Nested Workspace Correctness

- Separated the repository root used for stable graph file paths from the nested TypeScript or JavaScript workspace root used for configuration, source discovery, and relationship classification.
- Batch entries and graph nodes now retain repository-relative paths when a `tsconfig.json` or `jsconfig.json` is below the indexed repository root.
- Index-run scopes use the language workspace root while node IDs remain stable across the repository.
- Added regression coverage for nested workspace command construction, option parsing, batch paths, graph IDs, and relationship resolution.

### Discovery And Build-Output Exclusions

- Excluded `dist`, `build`, `coverage`, `node_modules`, and `.meridian` directories from TypeScript and JavaScript project discovery.
- Continued excluding TypeScript declaration files from source indexing.
- Updated the sample configuration, installation guide, indexing guide, architecture overview, README, and indexer support reference for JavaScript and JSX.

## Upgrade Notes

- No separate JavaScript worker is required. The packaged `TsIndexer` is now the shared TypeScript/JavaScript worker.
- Existing TypeScript behavior and CLI entry points remain compatible. `--skip-typescript` now skips `.ts`, `.tsx`, `.js`, and `.jsx` indexing together.
- Node.js 18 or later is required for the shared TypeScript/JavaScript indexing pass.
- JavaScript projects can use `jsconfig.json`; repositories without `tsconfig.json` or `jsconfig.json` are indexed from the requested root.
- Generated bundles under `dist`, `build`, and other standard output directories are not indexed.

- The TypeScript workspace build passes.
