# CodeMeridian v1.0.43

This release upgrades the MCP server to the stable 2.x SDK, adds typed MCP results, Tasks, and optional Apps, and substantially improves C# and TypeScript relationship resolution and diagnostics. It also fixes indexer shutdown behavior and includes dependency, security, deployment, and CI maintenance.

## Highlights

### MCP 2 Adoption

- Upgraded `ModelContextProtocol.AspNetCore` from 1.4.1 to 2.0.0 and added the 2.0.0 Tasks and Apps extensions.
- Preserved the existing authenticated `/sse` URL as a stateless Streamable HTTP endpoint.
- Verified the modern `2026-07-28` discovery path and down-level `2025-11-25` initialization and tool-call path.
- Added reviewed titles and safety annotations to all 62 MCP tools: read-only, destructive, idempotent, and open-world behavior is now explicit in discovery.
- Added private five-minute `tools/list` cache hints without caching graph-query results.
- Added bounded per-tool activities, counters, duration histograms, and structured operational logging without recording arguments, credentials, source, or task results.
- Kept JSON arguments canonical. No `[McpHeader]` parameter mirror is shipped because the SDK treats mirrored headers as integrity checks rather than alternate optional inputs.

### Typed Structured Results

Eight tools now advertise versioned JSON Schemas, return camel-case `structuredContent`, and retain useful Markdown for older or text-oriented clients:

- `build_minimal_context`
- `check_graph_freshness`
- `find_connection`
- `find_impact`
- `find_test_shield`
- `get_client_extension_contract`
- `list_client_extension_examples`
- `get_client_extension_example`

The new graph contracts provide bounded facts for paths, freshness, relationship completeness, impact, test shields, and minimal context. Payloads use stable empty collections, exclude arbitrary graph properties and source bodies, enforce size bounds, and are tested against their advertised schemas.

### MCP Tasks And Apps

- Added client-opted MCP Tasks for `rebuild_keyword_graph` and `classify_keywords`; ordinary synchronous calls remain supported.
- Added polling, cancellation propagation, TTL expiry, active-task capacity, execution timeout, result-size bounds, health reporting, and task metrics.
- Added two self-contained read-only MCP Apps for the client-extension contract and connection viewer.
- Added CSP, hostile-value injection, external-asset, accessibility, keyboard, and DOM-sink tests for both Apps.
- Kept Apps experimental and disabled by default. Non-App clients continue to receive the same Markdown and structured facts.

### Relationship Completeness And Indexer Accuracy

- Improved syntax-safe C# invocation evidence for typed parameters and members, lambdas, anonymous methods, `foreach`, `catch`, declaration patterns, casts, conditional access, object creation, and common static receivers.
- Added canonical and lexical type resolution plus stronger declaring-type, generic arity, optional-parameter, `params`, extension-method, inheritance, and interface candidate handling.
- Classifies calls that may belong to unindexed external bases conservatively instead of forcing incorrect local failures or edges.
- Separated TypeScript incremental emission from resolution: changed files are still the only files emitted, while all current project sources build the relationship catalog.
- Added a bounded TypeScript catalog fallback with explicit partial-catalog evidence, load duration, file count, and heap measurements.
- Persisted active TypeScript scope catalogs so removed project roots no longer contaminate relationship-confidence reports with historical runs.
- Added deterministic, diverse relationship-failure samples and production/test file-role breakdowns.
- Added `codemeridian report relationship-health`, with human-readable and bounded JSON output for outcomes, reasons, catalog completeness, file roles, and TypeScript catalog cost.
- Retained the conservative Low-confidence threshold for any known unresolved-local relationship after live evidence showed the remaining failures are actionable.

Live validation reduced the C# unresolved-local rate from 5.2% to 2.3%. The safe syntax-only slice did not reduce the C# indeterminate rate below its target; it remained 44.0%, primarily for fluent chains, return-value inference, and cross-file partial classes. Those cases remain honestly classified rather than receiving unsafe name-only edges. A controlled one-file TypeScript incremental run loaded the full 35-file catalog while emitting only changed-file data and reported zero unresolved-local or indeterminate relationships.

### Reliability, Security, And Maintenance

- Fixed forced shutdown in the TypeScript and HTML/CSS indexers by allowing pending asynchronous work and output to drain before process exit.
- Bounded configuration cleanup to 500 nodes per Neo4j transaction, preventing full re-indexes from exhausting the database transaction-memory limit while preserving configuration-usage keys.
- Added MCP Tasks and Apps flags to `.env.sample`, Docker Compose, and deployment documentation.
- Updated PostCSS to 8.5.24 and `@types/node` to 26.1.2.
- Refreshed lockfiles to resolve the `brace-expansion` vulnerability.
- Pinned GitHub CodeQL actions to 4.37.3.
- Added modern/down-level MCP wire snapshots, structured-schema snapshots, live acceptance coverage, task lifecycle tests, and App browser-DOM tests.

## Upgrade Notes

- Existing tool names and JSON arguments remain compatible. Structured tools still return useful Markdown.
- MCP client examples now use `"type": "http"` for stateless Streamable HTTP while retaining the existing `/sse` URL.
- MCP Tasks are enabled by default and remain client-opted. Disable their protocol surface with `Mcp__Tasks__Enabled=false`; ordinary tool calls are unaffected.
- MCP Apps are disabled by default. Enable them with `Mcp__Apps__Enabled=true` only for compatible hosts.
- Task state is process-local and is lost on restart. This release does not claim durable, multi-principal, or multi-replica task guarantees.
- The MCP 2 upgrade and typed result contracts do not require a graph rebuild.
- To replace historical relationship evidence and populate the improved catalogs, deploy the updated server/indexer and run:

  ```powershell
  dotnet run --project tools/Indexer -- . --force-full
  ```

- After deployment, restart clients that retained an old stateful MCP session.
