# CodeMeridian v1.0.54

This release fixes npm dependency restoration that could prevent TypeScript/JavaScript and HTML/CSS/SCSS indexing from starting.

## Highlights

- Restore both Node workers with `--legacy-peer-deps` to avoid npm Arborist's `Cannot read properties of null (reading 'edgesOut')` crash while resolving peer dependencies from outdated standalone worker lockfiles.
- Apply the same restore options to `npm ci`, the `npm install` fallback, and installs without a lockfile.
- Explicitly include development and optional dependencies so the workers retain `tsx` and the native esbuild binary even when `NODE_ENV=production` is set.
- Preserve restore failure exit codes so indexing does not continue after an unsuccessful install.

## Upgrade Notes

- Update the CLI with `dotnet tool update --global CodeMeridian.Indexer --version 1.0.54`, then retry indexing.
- The fix applies to the shared startup path for both Node workers. No application package changes are needed.
- No graph, cache, or data migration is required.
