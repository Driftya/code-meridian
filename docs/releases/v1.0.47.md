# CodeMeridian v1.0.47

This release improves relationship resolution across the C# and TypeScript indexers, adds safer incremental catalog behavior, expands MCP and Human Cognitive Seed capabilities, and updates the supported graph and dependency configuration.

## Highlights

### More Accurate C# Relationship Resolution

- Added compiler-backed semantic project inputs for C# indexing, including project implicit-using settings and restored package compile references.
- Used compiler-bound declaration locations to select overloads and inherited or external members before applying name and arity heuristics.
- Preserved full identities for nested C# types and members so same-named nested classes do not collapse into one graph node.
- Reduced false local failures for external framework, package, extension-method, and unknown-receiver calls while retaining explicit diagnostics for relationships that cannot be proven.
- Added regression coverage for overload resolution, external calls, nested types, implicit usings, package references, partial members, inferred locals, and factory-return chains.

### Safer TypeScript and JavaScript Graphs

- Kept the full TypeScript resolution catalog for incremental relationship analysis while emitting nodes and edges only for the changed files.
- Resolved nested functions, arrow-function variables, aliased heritage clauses, element-access calls, default exports, and callback scopes with their correct owners.
- Prevented unresolved callbacks, external imports, generic parameters, `as const` assertions, and same-name local functions from producing false local edges.
- Added regression coverage for scoped functions, callback properties, external imports, generic syntax, element access, and incremental catalog health.

### Relationship Health And Indexing Operations

- Calibrated relationship completeness using the rate of unresolved local candidates instead of lowering an entire project to `Low` for one failure.
- Kept indeterminate and external/unindexed outcomes visible without treating them as proven missing local relationships.
- Scoped TypeScript relationship catalogs by project and resolution scope, and stopped comparing incremental batch counts directly with full-index counts.
- Hardened malformed relationship metadata handling and raised the graph and incremental-cache contract versions so existing caches are refreshed safely.
- Added the `--external-only` indexing option and related CLI validation and documentation.

### MCP And Human Cognitive Seed Updates

- Added the Human Cognitive Seed change-context challenge, including interactive app resources, challenge state, answer and note models, tools, and tests.
- Improved required-argument error handling across MCP tools.
- Added feature configuration for MCP apps and updated structured MCP wire-contract baselines.
- Updated tool, agent, and project-context documentation to clarify how CodeMeridian should be used.

### Platform And Dependency Updates

- Updated Neo4j embedding configuration to 768 dimensions.
- Updated Neo4j, GitHub CodeQL, npm, NuGet, and test-runner dependencies.
- Updated OpenAPI package alignment for the MCP server and refreshed generated package-lock metadata.

## Upgrade Notes

- Run a full index after upgrading so existing C# and TypeScript relationship edges, health diagnostics, and nested-type identities are rebuilt with the new resolvers.
- Existing incremental index caches are invalidated automatically by the cache contract version change.
- Relationship totals may change after re-indexing because previously unresolved or indeterminate calls can now resolve locally, or can be classified more accurately as external or unindexed.
- If using vector embeddings, rebuild affected embeddings with the 768-dimensional configuration.
- No application-level migration is required for the Human Cognitive Seed challenge; its live acceptance tests remain opt-in where external services are required.
