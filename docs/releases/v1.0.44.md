# CodeMeridian v1.0.44

This release introduces Human Cognitive Seed support with durable, node-scoped change context for future coding sessions. It also strengthens MCP input validation, fixes a C# configuration-indexing failure, resolves the `nanoid` security advisory in every npm lockfile, and refreshes development dependencies and CodeQL.

## Highlights

### Human Cognitive Seed And Change Context

- Added the reusable `human-cognitive-seed` agent capability for preserving human-led decisions, constraints, limitations, assumptions, and follow-ups without treating AI-generated context as canonical truth.
- Added `record_change_context`, an idempotent MCP tool that stores one bounded statement against an exact existing code node.
- Added `get_change_context`, a read-only MCP tool with a versioned structured result and Markdown fallback.
- Stores change context as a separate attributed, unverified `KnowledgeDocument` linked to the target through `Mentions`; canonical code-node facts remain unchanged.
- Distinguishes `agent-synthesized`, `user-stated`, and explicitly confirmed `user-approved` provenance.
- Compares the current target source hash with the hash captured when context was recorded, exposing unchanged, changed, unknown, and orphaned states.
- Bounds statements, result counts, retry keys, and stored metadata, and excludes secrets, transcripts, chain-of-thought, commands, and source excerpts from the supported workflow.
- Added a dedicated Neo4j repository, application service, MCP contracts, dependency injection, and unit and integration coverage.
- Added a practical [Change Context User Guide](../change-context.md) with copy-paste prompts and an end-to-end repository example.

The MCP inventory now contains 64 tools. Nine tools advertise structured output, including the new `get_change_context` contract.

### Safer MCP Mutation Inputs

- Rejects blank node IDs, names, document content, project contexts, and external-concept identifiers before mutation.
- Treats blank optional document IDs as absent and normalizes blank optional source and project values to `null`.
- Rejects unknown external-concept relationship types and directions instead of silently substituting a default relationship.
- Added regression coverage for whitespace-only values, invalid enum values, invalid directions, and normalization behavior.

### Configuration Indexing Reliability

- Fixed C# configuration usage extraction when an element-access expression contains multiple arguments.
- Multi-argument access is now ignored safely instead of calling `SingleOrDefault()` and throwing.
- Added focused regression coverage for the failure case.

### Security, Dependencies, And CI

- Upgraded transitive `nanoid` from 3.3.16 to 3.3.18, resolving [GHSA-2v37-7h3g-55p8](https://github.com/advisories/GHSA-2v37-7h3g-55p8).
- Refreshed the root and all three standalone tool lockfiles so `npm audit --audit-level=high --workspaces=false` succeeds from every package directory.
- Updated JSDOM to 30.0.1, PostCSS to 8.5.25, TSX to 4.23.7, and the optional Rolldown platform bindings to 1.2.2.
- Updated GitHub CodeQL actions from 4.37.3 to 4.37.6.

## Upgrade Notes

- Existing MCP tool names and argument shapes remain compatible. The two change-context tools are additive.
- Deploy the updated MCP server before clients attempt to discover or call `record_change_context` or `get_change_context`.
- Change context can be attached only to an exact code node that already exists in the graph. No full graph rebuild is required solely for this feature.
- Stored context is attributed memory, not an instruction or verified fact. Clients and agents should re-evaluate it against current code, tests, documentation, and the user's current decision.
- `user-approved` provenance requires `userConfirmed=true` and should be used only after the user approves the exact stored summary.
- JSDOM 30 requires Node.js 22.22.2, 24.15.0, or 26 and later for the root MCP App test suite.
